# 开发过程记录（internal dev notes）

这个目录保存 `dsh-daily-report` 从调研、设计到第一至第三期实现的**历史开发过程文档**，用于回溯「当时为什么这样设计」。它们**不是**面向使用者的正式文档，也**不随 npm 包发布**。

## 三份文档

| 文件 | 原文件名 | 内容 | 写作时间 |
|---|---|---|---|
| [RESEARCH.md](RESEARCH.md) | dsh-每日简报-插件检索报告.md | 前期调研：DSH 插件市场里与「每日简报」相关的插件清单、覆盖度打分、兼容性判断，以及为什么没有可直接安装的现成方案 | 2026-11 |
| [DESIGN.md](DESIGN.md) | dsh-每日简报-功能设计方案.md | 功能设计稿：基于会话日志能拿到哪些数据、正文的分层摘要、工具统计维度、三层报告呈现、健康建议的数据源取舍、实现路线与需要拍板的三个问题 | 2026-11 |
| [HANDOVER.md](HANDOVER.md) | dsh-daily-report-交接说明.md | 交接说明：一至三期已实现的功能清单、代码结构、关键实现约定、真机验证记录、剩余人工验收项 | 2026-11-12 |

## 阅读须知

- **这些是开发过程记录，不是现状说明。** 文档描述的是当时开发者的机器环境（如 DSH `0.1.1-rc.2`）和当时的插件市场状态；版本号、插件收录情况、以及各表格里的指标都可能已经变化。
- **HANDOVER.md 的验收条目写于 2026-11-12，可能已过时。** 其中 §5「验收记录」与「仍需人工确认」反映的是那一天的测试结果和未完成项，不能当作当前版本的验收结论；当前的安装、配置与功能说明请看正式文档。
- **正式对外文档**：[GUIDE.md](../GUIDE.md)（安装、设置、隐私与功能说明）与仓库根 [README.md](../../README.md)（项目介绍与快速上手）。接口与数据形状以 [CONTRACT.md](../../CONTRACT.md) 为准。
- **路径已脱敏**：文档中的本机绝对路径已替换为占位符 —— `%USERPROFILE%` 表示当前用户主目录，`<repo>` 表示本仓库根目录，`<workspace>` 表示当时的开发者工作区根目录（仓库位于其下的 `plugin/` 子目录）。因此文中的 `plugin/lib/…` 等价于本仓库的 `lib/…`。
- **`_research/` 目录不在本仓库中。** 那是当时的调研物料（抓取的插件元数据、解包的 DSH 源码等），体积过大，未随仓库发布；文档里提到它只作为历史记录。
- 文档中的示例命令与路径（如 `E:\path\to\dsh-daily-report`）是通用示例，不代表真实安装位置。
